# Reproduction package for "Repositories, Contributors, and Continuity: An Empirical Study of Foundational Quantum Software"

This study applies established empirical software engineering techniques to a curated
set of *foundational* quantum software repositories, combining cross-repository activity
with contributor relationships to reveal contributor migration patterns and
cross-project knowledge transfer across repository boundaries.

The subject repositories are included as git submodules under [`projects/`](projects);
the subset selected for the analysis is defined in [`analysis/conf.yml`](analysis/conf.yml).

## Repository contents

- `analysis/`: the analysis pipeline. The Python package under `analysis/src` (the
  `repo-analysis` CLI) extracts contributor and commit history from the repositories;
  `analysis.R` and `network.R` produce the plots and the contributor network;
  `project_stats.py` computes per-project statistics; `conf.yml` selects the subject
  subset; `requirements.txt` and `requirements.R` pin the Python and R dependencies.
- `docker/`: the `Dockerfile`, `docker-compose.yml` and `env.sh` for the containerised
  analysis environment.
- `paper/`: the LaTeX sources of the paper (`main.tex`, `references.bib`) together with
  the figures and tables generated by the analysis (`generated/`).
- `projects/`: the analysed quantum software frameworks, included as git submodules
  (see [`.gitmodules`](.gitmodules)).
- `res/`: auxiliary resources used by the pipeline.
- `build/`: analysis outputs and the compiled paper, created by `make` (not tracked).

## Setup

### Prerequisites

- [Docker](https://docs.docker.com/get-docker/) with the `docker compose` plugin.
- Optionally [Nix](https://nixos.org/) and [direnv](https://direnv.net/) for a native
  development environment (a `flake.nix` and `.envrc` are provided).

### 1. Clone the repository

```
git clone --recurse-submodules <repository-url>
# or, in an existing clone:
git submodule update --init --recursive
```

Note that several submodules use SSH remotes (`git@github.com:…`) and require an SSH key
registered with GitHub. 

### 2. Reproduce the results

```
./docker/env.sh      # writes your UID/GID into .env (run once)
make repro_docker
```

This builds the Docker image and runs the full analysis pipeline inside a container,
producing the plots and the statistics table under `build/`.

For quickly evaluating the reproduction package, you can remove entries from the
`selected` list in [`analysis/conf.yml`](analysis/conf.yml); the pipeline then only
considers that subset of projects. Be aware that statistical results and visualisations
will differ in this scenario.

To additionally build the paper PDF from `paper/main.tex`, run `make all` inside the development shell described below.

### 3. Development environment (optional)

For an interactive shell in the analysis environment:

```
./docker/env.sh   # once, or after changing user
./docker.sh build
./docker.sh up
./docker.sh shell
```

Alternatively, with Nix and direnv installed, `direnv allow` drops you into the same
environment natively.

The analysis CLI is available as `analysis/src/cli.py`:

```
usage: repo-analysis [-h] [-v] {extract,analyse}

positional arguments:
  {extract,analyse}  sub command help
    extract          Extract the git history from the given repository
    analyse          Aggregate and analyse the extracted data

options:
  -h, --help         show this help message and exit
  -v, --verbose      increase verbosity
```

### Troubleshooting

**`fatal: detected dubious ownership in repository …`** — this happens when a
submodule's `.git` directory is owned by a different user than the one running the
container (e.g. left `root`-owned by an earlier container run). Restore consistent
ownership on the host:

```
sudo chown -R "$(id -u):$(id -g)" .git/modules/projects
```
